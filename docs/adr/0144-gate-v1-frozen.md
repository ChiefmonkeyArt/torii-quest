# ADR-0144: Torii Gate protocol v1 is frozen; readers verify signatures; conformance kit (G1 + G2)

- **Status:** Accepted
- **Date:** 2026-10-21
- **Deciders:** chiefmonkey ("do all the other things too")
- **Related:** ADR-0143 (the Gate is the product), ADR-0053 (liveness filter), ADR-0094 (beacon `p` tag), `GATEWAY_PROTOCOL.md`, `conformance/gateway-v1/`

## Context

The v0.1 draft described a URL intent and a signed-handshake event that never became the default. What actually runs:
- a kind-30078 heartbeat with NIP-40 expiry;
- a sanitising reader;
- an open visit to the destination's https page with `?torii-traveller=<hex>`;
- destination-side arrival modes.

The live directory scan did **not** check event signatures. A relay could inject a forged world listing.

## Decision

1. **`GATEWAY_PROTOCOL.md` is now v1 (frozen)** and describes the live protocol: heartbeat (§2), reader (§3), hop (§4), arrival (§5).
   - The reader rules match Quest's deployed reader exactly, including the clock-skew rescue, the zone-id rule and beacon owners.
   - Changes are additive extensions only (§8). A breaking change needs `version: 2`, an ADR and new fixtures.
   - The v0.1 draft moves to `docs/gateway-protocol-v0.1-draft.md`.
2. **Readers verify signatures (§3.1).** `readGateways(..., { verify: true })` drops records whose NIP-01 id or BIP-340 signature fails, and marks survivors `trust: 'signature-verified'`. The live scan in `main.js` passes `verify: true`.
3. **Conformance kit (G2)** in `conformance/gateway-v1/`:
   - `gate-v1.mjs`: the reference reader and writer check, with no Torii imports (`@noble` only);
   - deterministic signed fixtures (17 heartbeat cases + dedupe at freeze; 21 with the §8.1 world + travel cases, v0.2.937, 13 travel/arrival cases), regenerated by `tools/gen-gate-v1-fixtures.mjs`;
   - `check.mjs`: a CLI for checking your own heartbeat;
   - `reference-world/`: a single page with no engine that publishes, lists, travels and greets arrivals.
4. **CI freeze.** `tests/gateway/gate-v1-conformance.test.js` runs every fixture against both the kit and Quest's reader, writer, travel and arrival code. It also checks that Quest's `buildPresenceEvent` output passes the strict writer check.

## Consequences

- **Enables:**
  - any engine can prove compatibility without Torii code;
  - forged directory entries are dropped;
  - the spec and Quest can't drift apart.
- **Trade-offs:**
  - signature checks cost about 1 ms per record on the directory scan (≤200 records, off the game loop);
  - the clock-skew rescue means an expired record can stay listed for up to an hour after it was created; this is documented as spec behaviour.
- **Open:** the spec and kit are under the repo's GPL-3.0. A permissive licence for third-party adoption is an owner decision.
- **Verified:**
  - 35 conformance tests pass on both implementations;
  - the reference world loaded in a real browser, read the arrival claim, and listed 2 live, signature-verified worlds from a public relay.
